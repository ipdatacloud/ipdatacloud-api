# 快速开始

从开通到第一次拿到返回结果，四步。字段定义、响应示例与取值说明不在这里展开，六份接口文档在 `docs/api/` 下，入口见 [IP 归属地接口](api/ip-location.md)。

官网入口 [IP数据云 官网](https://www.ipdatacloud.com/?utm-source=github&utm-keyword=?5741)。

## 一、接入条件

1. 已在官网开通服务并取得 API Key。
2. 已准备 HTTP 客户端或 curl 等调用工具。
3. 密钥通过环境变量注入，不写入代码与版本库。

## 二、四步跑通

### 第 1 步 · 获取 API Key

先用免 Key 查询页 `ipdatacloud-ip-query` 核对单个 IP 的返回结构；需要六类产品字段与商用配额时，通过[官网](https://www.ipdatacloud.com/?utm-source=github&utm-keyword=?5741)注册并登录，选购对应的 API 套餐，再到「个人中心 - API管理」查看系统分配的专属 KEY。企业客户可联系客服申请商业套餐免费测试，客服电话 4006561191。

Key 按所选产品分配，调用哪个产品就用那个产品的 Key。开发、预发、生产环境分别使用独立密钥。

### 第 2 步 · 配置环境变量

```bash
export IPDATACLOUD_API_KEY="<YOUR_KEY>"
```

Windows PowerShell 的等价写法如下。

```powershell
$env:IPDATACLOUD_API_KEY = "<YOUR_KEY>"
```

若使用 `.env` 文件，须确认其已被 `.gitignore` 忽略。

### 第 3 步 · 发起首次调用

```bash
curl "https://api.ipdatacloud.com/v2/query?ip=140.224.61.98&key=$IPDATACLOUD_API_KEY"
```

接口地址为 `https://api.ipdatacloud.com/v2/query`，HTTPS GET 与 POST 都支持，输出 JSON，字符集 UTF-8。

请求参数只有两个，六个产品通用。


| 参数  | 类型   | 必填 | 说明                                    |
| ----- | ------ | ---- | --------------------------------------- |
| `ip`  | String | 是   | 要查询的 IP 地址，同时支持 IPv4 与 IPv6 |
| `key` | String | 是   | 产品密钥，按所选产品分配，用于权限校验  |

鉴权通过 URL 查询参数 `key` 传入，不需要额外请求头。

### 第 4 步 · 解析返回

响应顶层是 `code`、`msg`、`data` 三个字段。`code` 为 200 表示成功，此时 `data` 里是该产品的查询结果；`code` 为 500 表示失败，`data` 为空，原因写在 `msg` 里。

`data` 下的结构与内容按产品不同，字段定义以接口文档为准：


| 产品       | 结果子对象              | 接口文档                                 |
| ---------- | ----------------------- | ---------------------------------------- |
| IP归属地   | `data.location`         | [api/ip-location.md](api/ip-location.md) |
| IP风险画像 | `data.risk`             | [api/ip-risk.md](api/ip-risk.md)         |
| IP应用场景 | `data.scenes`           | [api/ip-scene.md](api/ip-scene.md)       |
| IP真人识别 | `data` 平铺             | [api/ip-human.md](api/ip-human.md)       |
| IP代理识别 | `data.proxy`            | [api/ip-proxy.md](api/ip-proxy.md)       |
| IP宿主信息 | `data.host_information` | [api/ip-host.md](api/ip-host.md)         |

解析时对可选字段做兜底，避免单字段缺失导致整条解析失败。字段范围按套餐开放，街道定位与风险标签需对应套餐。

## 四、状态码与错误处置

接口以 `code` 表达调用结果，客户端按 `code` 分支处理、按 `msg` 记录日志，不以 HTTP 状态判断业务结果。


| code | msg      | 含义                          | 客户端处理                       |
| ---- | -------- | ----------------------------- | -------------------------------- |
| 200  | success  | 请求调用成功                  | 解析`data`，做好字段兜底         |
| 500  | 失败信息 | 过期、次数不足、IP 类型错误等 | 依据`msg` 原因排查，避免盲目重试 |

常见现象与处理：


| 现象                               | 处理                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| `code: 500` 提示「key不能为空」    | 检查 URL 里有没有拼上`&key=`，再看密钥前后有没有多余空格或换行                   |
| `code: 500` 提示「接口次数已用完」 | 登录控制台看剩余次数，升级套餐或联系客服买增量包                                 |
| 部分字段为空                       | 不同套餐字段范围不同，街道定位、风险标签等需要对应套餐                           |
| IPv6 查询失败                      | 检查套餐是否支持 IPv6                                                            |
| 延迟高                             | 用连接池复用 HTTP 连接；高并发场景改本地离线库，把数据预加载进内存可以降到微秒级 |

额度判断依据 `code` 与 `msg`，不依赖 HTTP 状态码。错误日志不得打印含 `key` 的完整请求 URL 或完整请求头；上报问题须脱敏，移除客户名称、订单与真实业务日志。

## 五、连接、超时与重试

- 通过连接池复用 HTTP 连接，避免每次请求新建 TCP 连接，降低 HTTPS 握手与 TLS 协商开销；按并发量配置最大连接数与空闲超时。
- 给连接和读取分别设合理超时，避免线程被长请求占满。
- 仅对超时与可恢复的 `code: 500` 实施有限次退避重试，多实例场景加入随机抖动并设置重试上限；参数与鉴权错误须修正后重发。
- 批量调用在客户端限流，避免以高频重试占用额度。
- 日志仅记录耗时、`code` 与错误类别，不记录客户数据及含 `key` 的完整 URL。

在线接口 0.01s 返回结果，支持 1000 次/秒并发。定价页 `https://www.ipdatacloud.com/pricing/` 按产品分档公开调用次数与价格，全球IP归属地 API 从 5 万次 ￥18 起，超过 1000 万次详询客服；剩余次数在账号后台查看。
